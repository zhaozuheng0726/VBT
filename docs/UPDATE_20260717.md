This public snapshot adds curated, auditable evidence for the current VBT
encoder, rendering routes, scientific comparison, and VBT Studio engine. It
does not include the local thesis workspace or generated volume datasets.

The liquid compression-only Cycles comparisons measure 0.99496 and 0.99549
SSIM. This contract isolates Mode2 loss. End-to-end source-to-render metrics
also include voxelization and are intentionally kept separate.

## VBT Studio Runtime

The compact current-frame cache measures 4.967x-10.035x speedups over the
retained direct decoder contracts. Smoke and fire active-leaf compaction saves
62.1%-72.9% of fixed-equivalent cache memory. Mode2 leaves are all active, so
fluid contracts claim decode acceleration but no false compaction saving.

The frontend now accepts `--inspector-tab material|render|camera|export` for
deterministic automation and documentation capture. This does not alter VBT
decoding or rendered pixels.

## Scientific Baseline Contract

- RAW dimensions are `[X,Y,Z,T]`, with T fastest.
- zfp receives dimensions `(T,Z,Y,X)`.
- zfp compression may use OpenMP; Windows decompression uses the serial path.
- PSNR is normalized consistently as `-20 log10(NRMSE)`.
- J3/J4 are `minimum-rate`, not strict same-size comparisons, because zfp 4D
  cannot encode below 0.25 bpv.

At these operating points, VBT has lower MaxAbs error in J1-J8, with reductions
from 38.1% to 73.8% relative to zfp.

## Repository Scope

are tracked. Large `.vbtp`, RAW, VDB, Alembic, Blender, video, report, and paper
